# 페이지 기획 기준

확정한 구조는 프로필이 먼저 보이는 홈 한 페이지와 사례 상세 세 편이다. 홈은 `/`, 사례 상세는 `/work/[slug]`에서 제공한다.

```text
홈: 프로필 → 대표 작업 → AI 에이전트와 일하는 방식 → 연락
                └→ 카드 소개 펼침 → 상세 보기 ┬→ 다음 작업 상세 (있을 때)
                                           └→ 읽던 카드로 복귀
```

## 홈에 싣는 정보

| 위치 | 공개 홈의 구성 |
| --- | --- |
| 프로필 | 이름·직무, 짧은 자기소개, ‘대표 작업 보기’와 LinkedIn 링크를 먼저 보여준다. 소속명은 별도 공개 확인 전까지 싣지 않는다. |
| 첫 사례 · 제조 현장 | 처음에는 펼쳐 둔다. 제목 아래에 개인 기여, 상세 링크와 도해를 보여준다. |
| 후속 두 사례 · 정비 서비스와 산업 모니터링 | 처음에는 번호·분야·제목만 보인다. 제목을 누르면 페이지 이동 없이 해당 사례의 개인 기여와 상세 링크가 나타나고 이전 소개는 접힌다. |
| AI 에이전트와 일하는 방식 | 작업을 나눠 맡기는 기준과 결과를 판단하는 방식을 두 단락으로 설명한다. 본문 아래 링크는 이 포트폴리오의 공개 GitHub 저장소로 연결한다. |

모바일도 프로필 → 세 사례 → AI 에이전트와 일하는 방식 → 연락 순서다. [A안과 공개 홈의 차이](../design/design-guide.md#홈-a안과-공개-홈의-차이)에 두 항목을 결정한 근거를 기록했다.

## 사례 탐색과 상세
- 상세 하단에는 ‘대표 작업 목록으로’를 먼저 두고, 다음 사례가 있으면 ‘다음 작업’과 해당 사례의 제목을 하나의 링크로 표시한다. 순서는 홈의 `cases` 목록을 따르며 마지막 사례에서는 목록 복귀만 제공한다. 다음 편을 거쳐 목록으로 돌아오면 마지막으로 읽은 카드가 열린다.
- ‘대표 작업 보기’는 홈의 `#work`로, 사례 제목 버튼은 같은 자리에서 소개를 열거나 닫는다. ‘상세 보기’ 링크만 해당 상세로 이동한다. 상세에서는 사례 개요·역할·작업 범위를 읽고 ‘대표 작업 목록으로’를 누르면 `/#work`에서 방금 읽은 제목에 포커스가 돌아온다. 홈에서 연 상세에서 브라우저 뒤로가기를 해도 원래 홈 주소에서 같은 카드가 열린다.
- 상세의 ‘내 역할’에는 원본 구현과 작성 이력에서 확인한 개인 기여를 적는다. 개요와 도해는 제품의 동작을 설명하며 개인 기여나 실제 운영 사례의 증거로 쓰지 않는다. 수치에는 비교 조건과 측정의 한계를 붙인다. 공개가 확인된 정보만 사용한다.
- 제조 사례 상세는 기기별 화면 구조와 탭 전환 성능을 두 장으로 나눈다. 첫 장은 설비 수리 화면에서 공통 로직과 기기별 화면을 분리한 작업을 설명한다. 자재 수량을 표시한 두 화면은 기기 차이를 보여주는 정적 비교 도해다. 둘째 장과 홈의 성능 도해는 탭 10개를 열었을 때 클릭 후 대상 탭의 표시를 감지하기까지 걸린 시간의 중앙값을 비교한다.
- 정비 서비스 상세는 사용자 웹의 장바구니 재조회와 카드 승인 직전의 주문 수량 검사·서버 가격 검증을 구분한다. 결제 도해는 승인 전 검증 실패에 따른 선주문 취소 요청, 승인 후 주문 완료 성공에 따른 확정, 승인 후 주문 완료 실패에 따른 오류 안내를 별개의 경로로 보여준다.
- 산업 모니터링 상세는 도면 요소에 연결한 조회 키워드와 데이터 소스를 안내하고, 요소를 선택하면 연결된 차트와 표가 같은 조회 기준으로 갱신되는 흐름을 보여준다. 공개 주소는 `/work/scada-interaction`이고 기존 `/work/equipment-selection` 링크도 이 사례로 이동한다.
- 공용 UI는 외형·접근성을 담당한다. 어느 사례를 열지, 어떤 내용을 보여줄지는 화면이 결정한다.
