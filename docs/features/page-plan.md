# 페이지 기획 기준

확정한 구조는 프로필이 먼저 보이는 홈 한 페이지와 사례 상세 세 편이다. 홈은 `/`, 사례 상세는 `/work/[slug]`에서 제공한다.

```text
홈: 프로필 → 대표 작업 → AI 에이전트와 일하는 방식 → 연락
                └→ 사례 상세 → 대표 작업 목록 복귀
```

- 홈에서는 이름·역할을 먼저 보여주고 방문자가 소개에서 대표 작업으로 바로 갈 수 있게 한다.
- ‘대표 작업 보기’는 홈의 `#work`로, 세 사례 제목은 각각의 상세 주소로 연결한다. 상세에서는 사례 개요·역할·작업 범위를 읽고 ‘대표 작업 목록으로’를 누르면 `/#work`로 돌아온다.
- 상세 페이지는 맡은 역할, 해결한 문제, 선택한 설계와 결과를 구분한다. 수치에는 비교 조건과 측정의 한계를 붙인다. 공개가 확인된 정보만 사용한다.
- 제조 사례 상세는 기기별 화면 구조와 탭 전환 성능을 두 장으로 나눈다. 첫 장은 같은 자재를 입력하는 두 방식을, 둘째 장은 공용 측정값의 전후 비교를 보여준다.
- 정비 서비스 상세는 사용자 웹의 장바구니 재조회와 카드 승인 직전의 주문 수량 검사·서버 가격 검증을 구분한다. 결제 도해는 승인 전 검증 실패에 따른 선주문 취소 요청, 승인 후 주문 완료 성공에 따른 확정, 승인 후 주문 완료 실패에 따른 오류 안내를 별개의 경로로 보여준다.
- 산업 모니터링 상세는 도면 요소에 연결한 조회 키워드와 데이터 소스를 안내하고, 요소를 선택하면 연결된 차트와 표가 같은 조회 기준으로 갱신되는 흐름을 보여준다. 공개 주소는 `/work/scada-interaction`이고 기존 `/work/equipment-selection` 링크도 이 사례로 이동한다.
- 공용 UI는 외형·접근성을 담당한다. 어느 사례를 열지, 어떤 내용을 보여줄지는 화면이 결정한다.
